# /bind 回调实现计划：记录 + 同步更新（纯本地，零回环）

处理流程：RCS 推送 bind/unbind → 记台账（幂等闸门）→ 编码翻译（坐标→点位、料车编码→料车）→ 条件化更新 `cart_inventory` → 回应 RCS。全程不调用任何 AGV 绑定/解绑接口。

## 一、台账表（SQL 新文件 `wms/sql/20260901_rcs_bind_sync.sql`）

`wms_rcs_bind_record`：`req_code`（唯一索引=幂等键）、`slot_category/slot_code/carrier_category/carrier_code/invoke`（报文原文字段）、`handle_status`（PROCESSING/SUCCESS/UNMATCHED_POINT/UNMATCHED_CART/FAILED）、`handle_msg`、`raw_params`（报文原文）、时间戳。配套 `RcsBindRecordEntity` + `RcsBindRecordMapper`（MP BaseMapper）。

## 二、`CartInventoryService` 新增纯本地同步方法

`syncExternalBind(pointId, pointCode, cartId, cartCode, bind)`，`@Transactional`，注释明确禁止回调 RCS：
- **BIND（覆盖式，RCS 事实赢）**：① 清该车在其他点位的旧绑定（一车一位）；② 目标点位写入 `cart_id + arrive_time`；若原车不同且在途（arrive_time 为空）→ warn 日志（该预占任务将走异常路径）。
- **UNBIND（条件防迟到）**：`UPDATE ... SET cart_id=NULL, arrive_time=NULL WHERE point_id=? AND cart_id=?`；0 行命中也视为成功（迟到事件自动 no-op）。

## 三、rcs 模块新增 `RcsBindService` / `Impl`

`handleBindReport(RcsBindReportDTO)`：
1. **幂等**：插台账（PROCESSING）；`DuplicateKeyException` → 查记录，终态（SUCCESS/UNMATCHED_*）直接回成功；FAILED/PROCESSING 重处理。
2. **翻译**（失败记 UNMATCHED_* 且仍回成功——数据问题重试无意义）：
   - `slotCategory != "SITE"` → 落台账不处理（BIN 类暂不支持）；
   - `slotCode`（坐标）→ 点位：`RcsTaskMapper.xml` 新增 `selectPointIdByCoordinate`（LIMIT 1，多命中 warn）；
   - `carrierCode` → 料车：复用已有 `CartInventoryMapper.selectCartIdByCartCode`。
3. **执行**：调 `syncExternalBind`，成功→台账记 SUCCESS。
4. **异常**：台账记 FAILED 后向上抛 → controller 回失败码触发 RCS 重试（与 task 回调"总是成功"策略刻意不同）。

## 四、Controller 接入

`RcsReporterController./bind` 从占位改为调 `rcsBindService.handleBindReport(report)`：成功回 `{"code":"0","message":"success"}`，失败回 `{"code":"1","message":...}`（失败码取值待联调确认），更新注释。

## 五、不做（本次范围外）
BIN/仓位类别处理、定时对账任务、回调鉴权。
