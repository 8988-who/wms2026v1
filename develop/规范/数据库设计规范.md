# 数据库设计规范

> 适用范围：本项目（WMS）PostgreSQL 16 数据库设计与变更。
> 技术栈：PostgreSQL 16 + MyBatis-Plus 3.5.15（Spring Boot 4 / JDK 17）。
> 强制级图例：【强制】必须遵守；【推荐】默认遵守，特殊情况需评审说明；【参考】视场景采纳。
> 版本：v1.0　制定日期：2026-08-10

---

## 一、表前缀与归属（强制）

本项目数据库表按**前缀分治**，两类表遵循各自的历史约定，不得混用：

| 前缀 | 归属 | 审计字段命名约定 | 变更策略 |
|------|------|------------------|----------|
| `sys_` | 第三方脚手架（框架自带，如 `sys_user`/`sys_role`/`sys_dict`/`sys_config` 等） | `create_time` / `update_time` / `create_by` / `update_by` / `is_deleted` | **保持原样，禁止改动结构与命名**，仅在必要时加索引/约束 |
| `wms_` | 自研业务表（如 `wms_cart`/`wms_cart_item`/`wms_aisle`/`wms_point`/`wms_rcs_task` 等） | `created_time` / `updated_time` / `created_by` / `updated_by` / `is_deleted` | 以本规范为**唯一标准**，后续所有新表/改表均遵循 |
| `api_` | 接口日志类（如 `api_request_log`） | `created_time` / `updated_time` / `created_by` / `updated_by` | 参照 `wms_` 标准 |

- 【强制】**新建业务表一律使用 `wms_` 前缀**，并遵循下文 `wms_` 系列全部约定。
- 【强制】不得因看到 `sys_` 表使用 `create_time` 就在 `wms_` 表沿用；两套命名按前缀严格区分。
- 【强制】`sys_` 表若需扩展业务字段，应评估是否新建 `wms_` 关联表，避免污染脚手架表。

## 二、命名规范（强制）

### 2.1 表名
- 【强制】全小写字母 + 下划线分隔，`前缀_业务名`，如 `wms_cart_item`。
- 【强制】使用**单数**名词（`wms_cart` 而非 `wms_carts`）。
- 【强制】禁止 `tbl_`、`t_` 等无意义前缀。
- 【推荐】关联表命名为 `主体_从体`，如 `sys_user_role`、`sys_role_menu`。

### 2.2 字段名
- 【强制】全小写 + 下划线（snake_case），如 `product_code`、`sort_order`。
- 【强制】布尔/状态语义字段使用明确命名：删除标记 `is_deleted`，启用状态 `status`；禁止 `flag` 等无意义命名。
- 【强制】外键字段命名为 `关联表主体_id`，如 `model_id`（关联 `wms_cart_model`）、`location_id`。
- 【推荐】编码类字段统一后缀 `_code`（`cart_code`/`plant_code`），名称类 `_name`，数量类 `_quantity`/`_count`。

### 2.3 主键与序列
- 【强制】主键统一命名 `id`，类型 `int8`（`bigint`），由序列生成：`nextval('<table>_id_seq'::regclass)`。
- 【强制】序列 `MAXVALUE` 必须为 `9223372036854775807`（int8 上限），**禁止使用 `2147483647`（int4 上限）**。
  > 背景：`wms_cart`/`wms_cart_model` 曾误用 int4 序列上限，实体为 `Long` 会造成类型/容量不一致，须修正。
- 【强制】实体主键类型（Java `Long`）必须与 DB `int8` 一致，外键字段（如 `model_id`）同样使用 `int8`，禁止 int4 与 Long 混用。

### 2.4 约束/索引命名
- 【强制】唯一约束：`uk_<表简称>_<字段>`，如 `uk_item_product_code`、`uk_aisle_plant_code`。
- 【强制】普通索引：`idx_<表简称>_<字段>`，如 `idx_cart_item_cart_status`、`idx_point_aisle_id`。
- 【强制】外键：`fk_<子表简称>_<父表简称>`。
- 【推荐】联合索引字段顺序遵循最左前缀原则，高区分度/等值查询字段在前。

## 三、必备字段（强制）

`wms_` / `api_` 系列每张业务表**必须**包含以下字段：

| 字段 | 类型 | 约束/默认 | 说明 |
|------|------|-----------|------|
| `id` | `int8` | 主键，序列自增 | 主键 |
| `created_time` | `timestamp(6)` | `DEFAULT CURRENT_TIMESTAMP` | 创建时间，MyBatis-Plus `FieldFill.INSERT` |
| `updated_time` | `timestamp(6)` | `DEFAULT CURRENT_TIMESTAMP` | 更新时间，`FieldFill.INSERT_UPDATE` |
| `created_by` | `int8` | 可空 | 创建人 ID，`FieldFill.INSERT` |
| `updated_by` | `int8` | 可空 | 更新人 ID，`FieldFill.INSERT_UPDATE` |
| `is_deleted` | `int2` | `NOT NULL DEFAULT 0` | 逻辑删除：0-未删除，1-已删除 |
| `remark` | `varchar(500)` | 可空 | 备注（可选，视业务而定） |

- 【强制】审计时间字段的填充由 MyBatis-Plus `MetaObjectHandler` 统一处理，禁止业务代码手动赋值 `created_time/updated_time`。
- 【强制】新表**必须包含 `is_deleted`** 并配合实体 `@TableLogic`，禁止对业务数据执行物理 `DELETE`。
  > 背景：当前 `wms_cart`/`wms_cart_item`/`wms_aisle`/`wms_location`/`wms_point`/`wms_rcs_task` 等缺少逻辑删除列，配合物理外键（NO ACTION/RESTRICT）导致删除脆弱，须补齐。
- 【说明】`sys_` 脚手架表沿用 `create_time/update_time/create_by/update_by/is_deleted`，不受本节命名约束。

## 四、字段类型规范（强制）

| 语义 | 推荐类型 | 说明 |
|------|----------|------|
| 主键/外键/用户ID | `int8` | 统一，避免溢出 |
| 时间 | `timestamp(6)` | 全库统一；如需时区改用 `timestamptz` 并在评审说明 |
| 布尔/状态/删除标记 | `int2` | 0/1 语义，禁用 `char('Y'/'N')` 表布尔 |
| 金额 | `numeric(精度,标度)` | **禁止 `float`/`double` 存金额** |
| 短文本/编码 | `varchar(n)` | 明确长度：编码 ≤64，名称 ≤100，备注 ≤500 |
| 长文本/JSON 字符串 | `text` | 请求/响应参数等 |
| 结构化 JSON | `jsonb` | 如 `wms_rcs_task.payload`，实体用 `JacksonTypeHandler` + `@TableName(autoResultMap=true)` |

- 【强制】所有 `varchar` 必须显式指定长度，禁止无界文本滥用 `text`。
- 【强制】枚举语义字段（status 等）必须在 `COMMENT` 中写明每个取值含义。

## 五、约束与索引（强制/推荐）

### 5.1 唯一性约束（强制）
- 【强制】业务唯一键**必须建 DB 唯一约束**，不得仅靠应用层 `selectCount` 校验（并发下会击穿）。
  - 示例（本项目已具备，作为标杆）：`uk_item_product_code(product_code)`、`uk_item_cart_sort(cart_id, sort_order)`、`uk_aisle_plant_code(plant_code, aisle_code)`、`uk_location_plant_code`、`uk_point_plant_code`。
- 【强制】需要唯一语义的编码类字段（如 `sys_config.config_key`、`sys_dict.dict_code` 场景对应的业务键）应加唯一约束；若为脚手架表不便改，应在应用层加分布式锁并说明风险。
- 【推荐】应用层唯一校验 + DB 唯一约束**双保险**：应用层给友好提示，DB 兜底防脏数据，并捕获 `DuplicateKeyException` 转为业务异常。

### 5.2 索引（推荐）
- 【推荐】高频查询/连表字段建索引；外键列必须建索引（如 `idx_point_aisle_id`）。
- 【强制】**单表索引数不超过 5 个**（含唯一约束隐含索引）；新增索引前先检查是否被已有唯一约束覆盖，避免冗余。
  > 背景：`wms_cart_item` 索引接近上限，`idx_cart_item_product_code` 已被 `uk_item_product_code` 覆盖，属冗余可删。
- 【推荐】覆盖「实时计算 + 手动维护」双保险场景（如 `point_count`/`current_quantity`）时，为子查询条件建联合索引（`idx_cart_item_cart_status(cart_id, status)`）。

### 5.3 外键（强制）
- 【强制】外键 `ON DELETE` 策略必须与业务删除语义一致，并在设计评审中明确：
  - 明细随主表删除 → `CASCADE`（如 `wms_rcs_task_lifecycle` → `wms_rcs_task`）。
  - 禁止父表在有子记录时被删 → `RESTRICT`（如 `wms_aisle`/`wms_point` → `wms_location`）。
  - `NO ACTION` 需谨慎：物理删除父表会失败/报错（如 `wms_cart_item` → `wms_cart`），业务应改走逻辑删除。
- 【强制】既已配置物理外键，业务层不得再对父表执行物理 `DELETE`，一律走 `is_deleted` 逻辑删除。

## 六、触发器与数据库函数（强制）

- 【强制】触发器函数中引用的 `NEW.<列名>` 必须与目标表实际列名**完全一致**。
  > 反例（本项目现存 BUG）：`update_updated_at_column()` 引用 `NEW.updated_at`，而表列名为 `updated_time`，且未挂载任何 `CREATE TRIGGER`——该函数损坏且从未生效，须删除或修正为 `updated_time` 并正确挂载。
- 【强制】任何"由触发器自动维护"的字段（如 `point_count`），要么**真正创建并验证触发器生效**，要么在注释中如实说明"由应用层维护"，禁止注释与实现不符。
- 【推荐】数据一致性优先在应用层事务内维护；确需 DB 触发器时须编写迁移脚本 + 验证用例，纳入上线检查。
- 【推荐】自研维护 `updated_time` 优先使用 MyBatis-Plus 自动填充，不依赖 DB 触发器，避免双写冲突。

## 七、SQL 编写规范（强制）

- 【强制】**禁止 `SELECT *`**，必须显式列出所需字段。
- 【强制】`UPDATE`/`DELETE` 必须带 `WHERE`，且优先使用主键或索引字段。
- 【强制】**MyBatis-Plus 禁止 `${}` 拼接参数**，一律用 `#{}`（防 SQL 注入）。
  - 排序等动态字段确需动态拼接时，**必须走白名单校验**（字段名/排序方向枚举校验后再拼），禁止直接透传前端 `sortBy`/`order`。
    > 反例：`ORDER BY u.${queryParams.sortBy} ${queryParams.order}` 存在注入风险，须加白名单。
- 【强制】`updateById` 会忽略 null 字段；需要显式更新某字段（含置空）时使用 `LambdaUpdateWrapper` 明确 `set`。
- 【推荐】连表查询不超过 3 张表；更复杂的查询拆为多次单表查询 + 应用层组装。
- 【推荐】分页统一使用 MyBatis-Plus 分页插件，禁止手写 `limit/offset` 深分页而无优化。

---

## 八、实体映射规范（强制）

- 【强制】实体继承统一 `BaseEntity`（含 `id`/`createTime`/`updateTime`），子类**禁止重复声明**父类已有字段，防止字段遮蔽。
  > 说明：`wms_` 表列为 `created_time/updated_time`，通过 `@TableField(value="created_time")` 映射，不要在子类重复定义同名属性覆盖父类。
- 【强制】`@TableName` 的值必须与真实表名一致，变更表名前先确认数据库。
- 【强制】实体字段 Java 类型与 DB 列类型对应（`int8`↔`Long`、`int2`↔`Integer`、`timestamp`↔`LocalDateTime`、`jsonb`↔对象 + `JacksonTypeHandler`）。
- 【强制】逻辑删除字段用 `@TableLogic`，查询自动追加 `is_deleted = 0`。
- 【强制】审计字段使用 `@TableField(fill = FieldFill.INSERT / INSERT_UPDATE)`，由 `MetaObjectHandler` 填充。

---

## 九、数据库变更（DDL 脚本）管理（强制）

- 【强制】所有表结构变更必须以**可评审、可回滚的 SQL 脚本**提交，禁止在生产库手工改结构。
- 【强制】变更脚本需包含：正向 DDL、必要的数据迁移、回滚 DDL（或说明）。
- 【强制】上线前检查（对齐团队《开发规范指南》第十一节）：数据库变更脚本、缓存清理、回滚方案三者就绪。
- 【推荐】唯一约束/非空约束上线前先做存量数据清洗（去重/补默认值），避免加约束失败。
- 【推荐】大表加索引使用 `CREATE INDEX CONCURRENTLY`，避免锁表。

---

## 十、安全与合规（强制/死红线）

- 【强制】敏感信息（手机号、身份证、密钥等）在日志与返回体中脱敏，DB 中如需存储敏感数据应加密。
- 【强制】数据库连接口令**禁止硬编码**，通过环境变量/配置中心注入。
- 【强制】所有对外/跨系统写操作走参数化查询，杜绝拼接注入。

## 附录 A：`wms_` 新建表 DDL 模板

```sql
-- 序列（注意 MAXVALUE 为 int8 上限）
DROP SEQUENCE IF EXISTS "public"."wms_demo_id_seq";
CREATE SEQUENCE "public"."wms_demo_id_seq"
  INCREMENT 1 MINVALUE 1 MAXVALUE 9223372036854775807 START 1 CACHE 1;

DROP TABLE IF EXISTS "public"."wms_demo";
CREATE TABLE "public"."wms_demo" (
  "id"           int8         NOT NULL DEFAULT nextval('wms_demo_id_seq'::regclass),
  "demo_code"    varchar(64)  NOT NULL,
  "demo_name"    varchar(100),
  "status"       int2         NOT NULL DEFAULT 1,
  "created_by"   int8,
  "created_time" timestamp(6) DEFAULT CURRENT_TIMESTAMP,
  "updated_by"   int8,
  "updated_time" timestamp(6) DEFAULT CURRENT_TIMESTAMP,
  "is_deleted"   int2         NOT NULL DEFAULT 0,
  "remark"       varchar(500),
  CONSTRAINT "wms_demo_pkey" PRIMARY KEY ("id"),
  CONSTRAINT "uk_demo_code" UNIQUE ("demo_code")
);

CREATE INDEX "idx_demo_status" ON "public"."wms_demo" ("status");

COMMENT ON COLUMN "public"."wms_demo"."status" IS '状态(1-正常 0-禁用)';
COMMENT ON COLUMN "public"."wms_demo"."is_deleted" IS '逻辑删除(0-未删除 1-已删除)';
COMMENT ON TABLE  "public"."wms_demo" IS '示例业务表';
```

## 附录 B：对应实体模板

```java
@TableName("wms_demo")
@Data
@EqualsAndHashCode(callSuper = true)
public class Demo extends BaseEntity {

    /** 编码（全局唯一，DB uk_demo_code 兜底） */
    private String demoCode;

    /** 名称 */
    private String demoName;

    /** 状态：1-正常 0-禁用 */
    private Integer status;

    @TableField(value = "created_by", fill = FieldFill.INSERT)
    private Long createBy;

    @TableField(value = "updated_by", fill = FieldFill.INSERT_UPDATE)
    private Long updateBy;

    @TableLogic
    private Integer isDeleted;
}
```

> 说明：`id` / `createTime`(created_time) / `updateTime`(updated_time) 由 `BaseEntity` 统一提供，子类不重复声明。
