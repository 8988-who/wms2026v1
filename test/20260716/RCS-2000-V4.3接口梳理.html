RCS-2000 V4.3 接口梳理

海康机器人厂内物流机器人控制系统 — WMS系统对接完整指南

22 个 API 接口 9 个 SPI 回调 11 种车型流程 HMAC-SHA256 签名

📋 文档总览

本文档梳理了海康RCS-2000 V4.3机器人调度系统的全部对外接口，供WMS系统对接使用。接口分为两大类：

🔵 API 接口（WMS → RCS）

WMS主动调用RCS的接口，用于下发任务、查询状态、控制区域等。共22个接口，路径前缀 /rcs/rtas

🟣 SPI 回调接口（RCS → WMS）

RCS主动推送消息到WMS的回调接口，用于任务状态反馈、资源申请、告警上报等。共9个接口，路径可自定义

💡 接口方向说明 API接口：WMS作为HTTP客户端，向RCS发送POST请求。
SPI接口：RCS作为HTTP客户端，向WMS发送POST请求，WMS需要实现这些接口作为服务端。

🔧 通信协议

请求首部字段

字段名数据类型必须说明
Authorization字符串否固定格式: nonce="xxx",method="HMAC-SHA256",timestamp="2021-01-01T00:00:00+08:00"
Content-Type字符串否固定: application/json;charset=UTF-8
X-lr-appkey字符串否调度系统颁发给业务系统的唯一标识
X-lr-request-id字符串是业务请求唯一标识
X-lr-version字符串否API接口版本，保证向下兼容
X-lr-trace-id字符串否全链路追踪标识，响应中需原样返回
X-lr-source字符串否指令来源，便于调试

加密签名

如开启加密，需对请求进行签名。签名 = MD5(HMAC-SHA256(appSecret, 请求报文拼接原串))

参与签名的首部字段（按顺序）：AUTHORIZATION → HOST → X-LR-APPKEY → X-LR-REQUEST-ID → X-LR-SOURCE → X-LR-TRACE-ID → X-LR-VERSION

签名携带在查询参数 ?sign=xxx 中

响应格式

字段类型必须说明
code字符串是消息码，SUCCESS表示成功
message字符串否异常描述
dataJSON对象否业务数据

HTTP状态码

状态码说明
200处理成功，但仍需检查响应体code判断业务是否异常
401签名认证失败（签名无效/过期/appKey失效）
403权限不足
400客户端请求错误，不可通过重试解决
500服务端异常，可通过重试解决

通用响应Code

Code含义
SUCCESS成功
Err_Internal内部未知错误
Err_DataValidationFailed数据格式验证失败
Err_RequestDuplicate请求重复
Err_InvalidVersion请求版本不合法

🔵 API 接口（WMS → RCS）

以下接口由WMS主动调用RCS，路径前缀统一为 /rcs/rtas

任务组接口 国标
POST /rcs/rtas/api/robot/controller/task/group
幂等
功能：任务组是任务的集合，当任务间有相互关系时，需要先调用此接口描述任务组策略。任务策略包括按组顺序出库策略、按组分配策略、载具整理策略。顺序出库时按 groupSeq 从小到大下发。

请求参数

参数名类型必须说明
groupCode字符串是任务组编号，全局唯一
strategy字符串是执行策略: GROUP_SEQ(顺序出库) / GROUP_ASSIGN(按组分配) / GROUP_CARRIER_ADJUST(载具整理)
strategyValue字符串否策略值。GROUP_SEQ时: 0=组间组内无序, 1=组间组内有序, 2=组间有序组内无序, 3=组间无序组内有序
groupSeq整数否组顺序号(1~9999999999)
targetRouteJSON对象否执行任务的下一个目标位置，控制同一工作台的顺序
dataJSON数组是任务数据数组，包含 robotTaskCode 和 sequence
请求示例
{ "groupCode": "2e0d1ae0481f48b78b6a217ac2b54eb4", "strategy": "GROUP_SEQ", "strategyValue": "1", "groupSeq": 10, "targetRoute": { "type": "ZONE", "code": "A2" }, "data": [ { "robotTaskCode": "0a17e361eb52...", "sequence": 1 }, { "robotTaskCode": "1b30143f3291...", "sequence": 2 } ] }
任务下发接口 国标
POST /rcs/rtas/api/robot/controller/task/submit
幂等
功能：WMS发送任务请求，RCS生成任务执行单并下发执行。这是最核心的接口，所有搬运任务都通过此接口下发。taskType决定任务流程类型（潜伏车/叉车/CTU/滚筒车等）。

请求参数

参数名类型必须说明
taskType字符串是任务类型。预制值: PF-LMR-COMMON(潜伏车搬运), PF-FMR-COMMON(叉车搬运), PF-CTU-COMMON(CTU搬运), PF-CMR-COMMON(滚筒车搬运), PF-LMR-INIT-CARRIER(潜伏车指定载具初始化), PF-DETECT-CARRIER(探测载具搬运), PF-CTU-LOADER-IN(CTU工作站入库), PF-CTU-CONVEYOR-IN(CTU输送线入库), WMS-PF-CTU-ALLOC-WALL-OUT(CTU缓存架出库), WMS-PF-CTU-ALLOC-WALL-IN(CTU缓存架入库)
targetRoute对象数组是执行步骤集合。每个步骤含 type(目标类型)、code(目标编号)、operation(操作: COLLECT取货/DELIVERY送货/ROTATE旋转)
initPriority整数否初始优先级(1~120)，数值越大优先级越高
deadline时间否任务截止时间，如 2021-04-04T12:23:55Z
robotType字符串否机器人选择范围: GROUPS(资源组) / ROBOTS(指定车号)
robotCode字符串数组否与robotType匹配的资源标识
interrupt整数否能否打断: 1=可打断, 0=不可打断(默认)
robotTaskCode字符串否外部任务唯一编号，为空则系统生成
groupCode字符串否任务组编号
extraJSON对象否扩展字段，可含 angleInfo(角度)、carrierInfo(载具信息)、crossVisionDoor(视觉门)、pickStationCode(拣选站)
💡 targetRoute.type 目标类型枚举 ZONE(区域), SITE(站点), STORAGE(仓位), MAT_LABEL(物料标签), CARRIER(载具), STACK(巷道), EQPT(外部设备), PTL_WALL(CTU缓存架), CARRIER_TYPE(载具类型), BIN_TYPE(仓位类型), AREA_STATION(区域工作台)
潜伏车搬运示例
{ "taskType": "PF-LMR-COMMON", "targetRoute": [ { "type": "CARRIER", "code": "P00001" }, { "type": "SITE", "code": "WS001", "operation": "DELIVERY" } ], "initPriority": 50 }
CTU工作站入库示例
{ "taskType": "PF-CTU-LOADER-IN", "targetRoute": [{ "type": "EQPT", "code": "222" }], "extra": { "carrierInfo": [ { "carrierType": "3", "carrierCode": "jieb1", "layer": 0 }, { "carrierType": "3", "carrierCode": "jieb2", "layer": 1 } ] } }
任务继续执行接口
POST /rcs/rtas/api/robot/controller/task/extend/continue
幂等
功能：一个任务包含多个步骤时，每个步骤完成后需要WMS通过此接口驱动下一个阶段执行。第一个步骤也需要通过此接口启动。如果步骤设置为自动开始则非必须调用。
参数名类型必须说明
triggerType字符串是触发类型: SITE(站点) / CARRIER(载具) / ROBOT(车号) / TASK(任务链编号)
triggerCode字符串是与triggerType对应的触发编号
targetRoute对象否下一个目标位置（含type, code, operation）
extra对象否扩展参数
请求示例
{ "triggerType": "TASK", "triggerCode": "1a17e361eb5248bfab0508e4709f085f5", "targetRoute": { "type": "ZONE", "code": "D1", "operation": "COLLECT" } }
任务取消接口 国标
POST /rcs/rtas/api/robot/controller/task/cancel
幂等
功能：取消当前任务并返回结果。支持在取消时同时下发新任务。V4.2.8+支持按车号robotCode或载具号carrierCode批量取消。取消类型：CANCEL(软取消，生成回库任务) / DROP(人工介入，硬取消)。
参数名类型必须说明
robotTaskCode字符串否任务号（批量取消时可不传）
cancelType字符串是CANCEL(软取消) / DROP(人工介入硬取消)
carrierCode字符串否回库载具编号
robotCode字符串否机器人编号（批量取消用）
reason字符串否取消原因
returnTaskType字符串否软取消回库任务类型，默认 PF-TASK-CANCEL-RETURN
targetRouteJSON对象否新任务目标位置
任务优先级设置接口 国标
POST /rcs/rtas/api/robot/controller/task/priority
幂等
功能：任务创建后、结束前，随时调整任务优先级参数（初始优先级和截止时间）。调度系统会根据繁忙程度、工作状态等综合判定实际优先级。
参数名类型必须说明
robotTaskCode字符串是任务号
initPriority整数是优先级(1~120)
deadline时间否截止时间
区域暂停与恢复机器人接口 国标
POST /rcs/rtas/api/robot/controller/zone/pause
幂等
功能：让指定区域内的机器人暂停（FREEZE运行急停）或恢复（RUN）运行。
参数名类型必须说明
zoneCode字符串是调度管控区区域编号
mapCode字符串否地图编号（临时区域时需要）
invoke字符串是FREEZE(运行急停) / RUN(恢复)
区域归巢机器人接口 国标
POST /rcs/rtas/api/robot/controller/zone/homing
幂等
功能：让指定区域内的机器人前往预定的停放区域。支持归巢后自动关机，并预设开机时间点，适应工厂长时间休假场景。
参数名类型必须说明
mapCode字符串否地图编号（只传地图则整个地图的车归巢）
zoneCode字符串否需归巢的区域编号
zoneCodes字符串数组否区域编号集合（须同一地图）
autoShutdown字符串是YES(关机) / NO(不关机)
bootTime时间否预设开机时间（分钟精度），autoShutdown=YES时生效
expireTime时间否归巢超时时间（秒精度），默认10分钟
区域驱离机器人接口 国标
POST /rcs/rtas/api/robot/controller/zone/banish
幂等
功能：将区域内的机器人驱离，并禁止其他机器人通过该区域。支持驱离后暂停、通知上层系统、指定目标区域。
参数名类型必须说明
zoneCode字符串否需驱离的区域编号
zoneCodes字符串数组否区域集合
targetZoneCode字符串否机器人前往的目标区域
controlMode字符串否0=调度到区域外, 1=暂驻区, 2=指定区域
pause字符串否完成后是否暂停: 0=不暂停, 1=暂停
report字符串否完成后是否通知: 0=不通知, 1=通知
invoke字符串否BANISH(驱离) / RUN(恢复)
区域封锁与恢复接口 国标
POST /rcs/rtas/api/robot/controller/zone/blockade
幂等
功能：封锁指定区域，区域外的机器人不能进入（但区域内的机器人不需要离开）。解除封锁后限制取消。与驱离的区别：驱离要求区域内机器人离开，封锁只阻止外部进入。
参数名类型必须说明
zoneCode字符串是需封锁的区域编号
invoke字符串是BLOCKADE(封锁) / OPENUP(解封)
pause字符串否封锁后是否暂停区域内机器人
report字符串否完成后是否上报
disableSite数字否是否禁用点位: 0=否, 1=是(默认)
enableSite数字否是否启用点位: 0=否, 1=是(默认)
载具与站点绑定接口 国标
POST /rcs/rtas/api/robot/controller/carrier/bind
幂等
功能：将载具绑定到站点，代表载具放置在该站点上。前提：载具与站点均未被任务占用。需在调度系统中录入载具才能使用。
参数名类型必须说明
carrierCode字符串是载具编号/别名
siteCode字符串是站点编号/别名
carrierDir整数否货架方向: [0, 90, 180, -90, 360]
载具与站点解绑接口 国标
POST /rcs/rtas/api/robot/controller/carrier/unbind
幂等
功能：解除载具与站点的绑定关系。载具或站点编号至少传一个。
参数名类型必须说明
carrierCode字符串否载具编号
siteCode字符串否站点编号
存储对象与搬运对象绑定解绑接口
POST /rcs/rtas/api/robot/controller/site/bind
幂等
功能：存储对象（站点/仓位）与搬运对象（货架/托盘/料箱）的绑定与解绑。比载具绑定接口更通用，支持仓位绑定和堆叠场景。
参数名类型必须说明
slotCategory字符串否存储对象种类: SITE(站点) / BIN(仓位)
slotCode字符串否存储对象编号
carrierCategory字符串否搬运对象种类: POD(货架) / PALLET(托盘) / BOX(料箱)
carrierCode字符串否载具编号
carrierDir整数否货架方向: [0, 90, -90, 180, 360]
invoke字符串是BIND(绑定) / UNBIND(解绑)
colCount整数否堆叠层号
载具禁用与启用接口 国标
POST /rcs/rtas/api/robot/controller/carrier/lock
幂等
功能：禁用载具后，该载具和所处站点不会被任务分配（已分配任务需执行完成）。启用为逆操作。
参数名类型必须说明

站点禁用与启用接口 国标
POST /rcs/rtas/api/robot/controller/site/lock
幂等

参数名类型必须说明

invoke字符串是LOCK(禁用) / UNLOCK(启用)
外设执行通知接口【返回0】
POST /rcs/rtas/spi/wcs/robot/eqpt/notify
幂等
功能：外设执行完成后通知RCS，与SPI请求外设接口对应。用于电梯到位、自动门开关、装卸机取放货等外设协同场景。此版本返回码为"0"。
参数名类型必须说明

actionStatus字符串是执行状态: "1"自动门开门到位, "2"关门到位, "3"电梯开门到位, "4"物料到达楼层, "5"取货, "6"放货, "7"到达
siteCode字符串是分配的站点编号
⚠️ 注意 另有一个V4.2.8版本的外设通知接口 /spi/wcs/robot/eqpt/notifyGbt，功能相同，但返回码改为 SUCCESS。建议WMS对接时确认RCS使用哪个版本。

参数名类型必须说明
siteCode字符串是站点编号
nextTaskTime字符串是预调度时间(0~3600秒)，0=清空预调度
robotType字符串否机器人类型
priority整数否优先级(1~120)
taskCount整数否预调度任务数，默认1

🟣 SPI 回调接口（RCS → WMS）

💡 重要提示 SPI接口由RCS主动调用WMS，WMS需要实现这些接口作为HTTP服务端。接口地址可在RCS系统设置-扩展管理-数据同步权限-业务通知中自定义配置。
任务执行过程回馈接口 国标 SPI
POST /api/robot/reporter/task
功能：RCS将任务执行过程中的消息反馈给WMS，包括任务开始、载具搬出储位、任务完成等关键节点。这是WMS跟踪任务进度的核心回调。

请求参数（RCS发给WMS）

参数名类型必须说明
robotTaskCode字符串是任务号
singleRobotCode字符串是执行任务的机器人编号
extra.values.method字符串是消息方法: start(任务开始), outbin(走出储位), end(任务完成)
extra.values.carrierCode字符串是载具编号
extra.values.slotCode字符串否当前站点编号（走出储位时为起点，任务完成时为目标点）
💡 WMS响应 WMS收到回馈后需返回 {"code":"SUCCESS","message":"成功","data":{"robotTaskCode":"任务号"}}
请求资源接口 SPI
POST /api/robot/reporter/resource
功能：RCS向WMS请求资源分配。典型场景：机器人需要搬运货架到目的地，但目的地未指定，RCS向WMS申请一个站点。WMS需在响应中返回分配的资源。

请求参数（RCS发给WMS）

参数名类型必须说明
robotTaskCode字符串是任务号
applyType字符串是申请类型: APPLY_SITE(存储位置), APPLY_BIN(仓位), APPLY_PTL_BIN(分播位), APPLY_CARRIER(载具)
resourceType字符串是资源类型: CARRIER/SITE/ZONE
resourceCode字符串是资源编号

WMS响应（需返回分配的资源）

{ "code": "SUCCESS", "message": "成功", "data": { "type": "SITE", "code": "WS001" } }
请求外设接口 SPI
POST /api/robot/reporter/eqpt
功能：RCS向WCS（或WMS）请求外设控制。典型场景：机器人需要使用电梯，RCS向WCS申请电梯资源。WCS控制电梯到位后，再通过外设执行通知接口告知RCS。
参数名类型必须说明
eqptCode字符串是设备编号
eqptName字符串是设备名称
taskCode字符串是任务号
method字符串是执行方法: CANCEL(取消), APPLY_TO_AGV(接料), APPLY_FROM_AGV(送料), ARRIVED(到达), RELEASE(离开), APPLY_LOCK(门开), RELEASE_EQPT(释放门), APPLY_RESOURCE(电梯申请), EXECUTE_TASK(电梯执行), RELEASE_RESOURCE(释放电梯)

🔄 任务下发流程示例

不同车型和场景使用不同的 taskType，以下是11种典型流程：

3.1 潜伏车通用流程 (PF-LMR-COMMON)

最常见的搬运场景：机器人到货架位置顶起货架，搬运到目标站点。

{ "taskType": "PF-LMR-COMMON", "targetRoute": [ { "type": "CARRIER", "code": "P00001" }, { "type": "SITE", "code": "WS001" } ], "initPriority": 1 }

3.2 潜伏车指定载具初始化流程 (PF-LMR-INIT-CARRIER)

起点不需要绑定载具，直接指定载具编号初始化搬运。

{ "taskType": "PF-LMR-INIT-CARRIER", "targetRoute": [ { "type": "SITE", "code": "XXXXXXX" }, { "type": "ZONE", "code": "SL2", "extra": { "angleInfo": { "code": "90" } } } ], "extra": { "carrierInfo": [{ "carrierType": "5", "carrierCode": "P00001" }] }, "interrupt": 0 }

3.3 探测载具搬运流程 (PF-DETECT-CARRIER)

机器人到站点探测载具后搬运，用于不确定载具是否在位的情况。

{ "taskType": "PF-DETECT-CARRIER", "targetRoute": [ { "type": "SITE", "code": "站点1" }, { "type": "SITE", "code": "站点2" } ], "extra": { "carrierInfo": [{ "carrierType": "66" }] } }

3.4 CTU通用流程 (PF-CTU-COMMON)

CTU（料箱机器人）搬运料箱到仓位。

{ "taskType": "PF-CTU-COMMON", "targetRoute": [ { "type": "CARRIER", "code": "C0001" }, { "type": "STORAGE", "code": "仓位编号" } ] }

3.5 CTU工作站入库流程 (PF-CTU-LOADER-IN)

从工作站（装卸机/输送线）将料箱入库，支持多层料箱同时入库。

{ "taskType": "PF-CTU-LOADER-IN", "targetRoute": [{ "type": "EQPT", "code": "222" }], "extra": { "carrierInfo": [ { "carrierType": "3", "carrierCode": "jieb1", "layer": 0 }, { "carrierType": "3", "carrierCode": "jieb2", "layer": 1 } ] } }

3.6 CTU缓存架出库流程 (WMS-PF-CTU-ALLOC-WALL-OUT)

从CTU缓存架（分播墙）将料箱出库。

{ "taskType": "WMS-PF-CTU-ALLOC-WALL-OUT", "targetRoute": [ { "type": "CARRIER", "code": "jieb1" }, { "type": "PTL_WALL", "code": "900003" } ] }

3.7 CTU缓存架入库流程 (WMS-PF-CTU-ALLOC-WALL-IN)

将料箱入库到CTU缓存架仓位。

{ "taskType": "WMS-PF-CTU-ALLOC-WALL-IN", "targetRoute": [{ "type": "STORAGE", "code": "R900003A03021" }], "extra": { "carrierInfo": [{ "carrierType": "3", "carrierCode": "jieb1" }] } }

3.8 CTU输送线探测入库流程 (PF-CTU-CONVEYOR-IN-DETECT)

从输送线探测料箱后入库。

{ "taskType": "PF-CTU-CONVEYOR-IN-DETECT", "targetRoute": [{ "type": "EQPT", "code": "777" }] }

3.9 CTU输送线入库流程 (PF-CTU-CONVEYOR-IN)

从输送线指定料箱入库。

{ "taskType": "PF-CTU-CONVEYOR-IN", "targetRoute": [{ "type": "EQPT", "code": "777" }], "extra": { "carrierInfo": [{ "carrierType": "3", "carrierCode": "901" }] } }

3.10 叉车通用流程 (PF-FMR-COMMON)

叉车搬运托盘到区域。

{ "taskType": "PF-FMR-COMMON", "targetRoute": [ { "type": "CARRIER", "code": "PA0001" }, { "type": "ZONE", "code": "SL2" } ], "interrupt": 0 }

3.11 滚筒车通用流程 (PF-CMR-COMMON)

滚筒车站点到站点搬运。

🎯 WMS对接最佳实践

核心对接流程

1. 初始配置

在RCS系统中注册第三方应用，获取 appKey 和 appSecret。配置SPI回调地址（业务通知中设置）。开启所需业务通知：ZONE_HOMING、ZONE_BANISH、AMR_ALARM、TASK_ALARM、BIND等。

2. 基础数据同步

WMS需要与RCS保持载具、站点、仓位等基础数据同步。通过载具绑定/解绑接口维护载具位置，通过绑定解绑通知SPI接收RCS侧的变更。

3. 下发搬运任务

WMS调用 /api/robot/controller/task/submit 下发任务，根据车型选择正确的 taskType。如果任务有多个步骤且非自动开始，需通过 task/extend/continue 驱动每个步骤。

4. 接收任务回馈

WMS实现 /api/robot/reporter/task SPI接口，接收任务开始(start)、走出储位(outbin)、任务完成(end)等回馈，更新WMS侧任务状态和库存位置。

5. 处理资源申请

当RCS需要WMS指定目标位置时，会通过 /api/robot/reporter/resource 申请资源。WMS需在响应中返回分配的站点/仓位/区域。

6. 异常处理

实现机器人告警和任务告警SPI接口，接收异常推送。WMS可据此触发告警通知、任务重试等逻辑。可通过任务取消接口取消异常任务。

7. 状态查询

WMS可主动调用查询接口获取任务状态、机器人状态、载具状态，用于监控看板或补偿机制。

💡 接口调用顺序（典型出库流程） 1. 物料绑定（将物料绑定到货架）→ 2. 任务下发（搬运货架到工作站）→ 3. 接收start回馈（任务开始）→ 4. 接收outbin回馈（货架离开储位，WMS更新库存）→ 5. 接收end回馈（货架到达工作站，WMS更新位置）→ 6. 拣货完成后下发回库任务
⚠️ 关键注意事项
  • 所有API接口均支持幂等，重复调用不会产生副作用
  • 超时设置：连接超时30秒，数据返回超时60秒
  • 签名认证合法请求时间建议不超过120秒
  • 载具绑定/解绑前需确保载具和站点均未被任务占用
  • 批量取消任务时，cancelType必须为DROP，且不能取消CTU车型
  • SPI接口地址可在RCS业务通知中自定义配置
  • 任务状态：QUEUE→WAIT→EXECUTING→FINISHED/CANCELLED/MANUALED
